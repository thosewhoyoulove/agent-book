# 首个增量架构

## 边界

`agent-core` 只处理模型响应、消息历史、工具注册、参数校验和工具执行。它不依赖 React，也不负责网络传输或持久化。

`agent-runtime` 在核心循环之上提供生命周期状态和事件。状态转换由运行时控制，UI 只消费事件和快照。

`book-web` 将同一套执行模型用于教学模拟器。模拟器没有单独编写一套“动画逻辑”，而是把每一次模型调用、工具校验、工具执行和消息追加记录为可回放步骤。

## 数据流

```text
用户输入
  -> runAgent()
  -> LLM Provider
  -> LlmResponse
  -> Tool Registry / Tool Executor
  -> Message History
  -> Runtime Event
  -> React Simulator
```

## 教学取舍

Mock LLM 用预先定义的决策序列表现“模型决定调用工具”的现象。它不代表真实模型内部推理，也不模拟隐藏推理文本。这样可以让实验确定、可测试，并且明确区分模型生成与程序执行。

工具参数使用 Zod schema 校验。工具执行失败会转换为结构化 `tool` 消息继续交给模型，是否重试由模型下一次响应决定；运行时仍以最大步数、取消和超时作为硬边界。
